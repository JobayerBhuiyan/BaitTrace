# HDR004 Date header is malformed or contradicts delivery

## What it detects

The `Date` header cannot be parsed as RFC 5322, or it disagrees with the
timestamps in the `Received` chain by more than 24 hours.

The check does **not** compare `Date` against the current clock. A verdict
that changes depending on when it was run is not reproducible, and
reproducibility is what lets a score from six months ago still be explained.

## Why it matters

A forged `Date` is used to bury a message in a mailbox (back-date it so it
vanishes under older mail) or to fake urgency (a "your account expires
today" mailed with tomorrow's date). A date a mail client would never have
produced is also a fingerprint of template assembly.

Relay clocks genuinely disagree, which is why the drift tolerance is a full
day.

## Example

```
Date: not a date
```

or a `Date` of 1 January 2020 on a message whose `Received` chain timestamps
it in August 2026.

## Known false positives

Badly configured relay clocks drift. The 24-hour tolerance exists to absorb
that. Missing `Date` is not this rule; a missing date is left to other
hygiene checks so a single omission does not fire twice.
