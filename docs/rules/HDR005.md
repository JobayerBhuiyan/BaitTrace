# HDR005 Return-Path does not match the sender

## What it detects

The envelope sender (`Return-Path`), where bounces go, is a different
registrable domain than the `From` header a reader sees.

## Why it matters

The address a human sees and the address that owns the bounce are supposed
to be the same organisation. When they differ, either a provider is sending
on someone's behalf (legitimate) or the visible sender is decoration
(phishing). The AUTH analyzer (M4) is what distinguishes those cases via
SPF / DMARC alignment; until then this rule is corroborative and is
weighted down when bulk-mail headers are present.

## Example

```
Return-Path: bounce@mail-secure.example
From: Microsoft Support <account@micros0ft-login.example>
```

Bounces go to `mail-secure.example`; the reader sees
`micros0ft-login.example`.

## Known false positives

Mailing lists, forwarders, and email service providers legitimately rewrite
the envelope sender. The benign `newsletter.eml` sample is this shape on
purpose: HDR005 fires, the weight drops because of bulk headers, and the
score stays at 16.
