# HDR001 Duplicate single-occurrence header

## What it detects

A header that RFC 5322 allows only once — `From`, `Subject`, `Date`,
`Message-ID`, `Reply-To`, or `Sender` — appears more than once. Different
software along the path may act on different values.

A second `From` is the dangerous case: it exploits disagreement between the
header an MTA validated and the header a mail client chooses to display.
That is why headers are stored as an ordered sequence with duplicates
preserved. A dict-based model would destroy this evidence before the
analyzer could see it.

## Why it matters

Some clients display the first `From`, some the last. Gateways validating
SPF/DKIM typically see one of them. When they disagree, the address a human
trusts is not the address that was authenticated.

Duplicate `From` is weighted higher than duplicate `Subject`.

## Example

```
From: Microsoft Support <support@microsoft.com>
From: account@thief.example
```

Evidence lists every occurrence with its index (`header:From#0`,
`header:From#1`).

## Known false positives

Badly written bulk mailers occasionally emit a duplicate `Reply-To` or
`Subject` without malicious intent. Duplicate `From` is much harder to
excuse.
