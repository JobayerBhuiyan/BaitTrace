# IDN900 Sender is on the operator's allowlist

This is a **suppressor**, not an indicator. It argues against suspicion.

## What it detects

The sending domain or address matches an entry in the operator's
configuration (`allowlist.domains` or `allowlist.addresses` in
`baittrace.toml`). When it fires, other identity findings for that sender
are skipped: the operator has already vouched for them.

## Why it matters

A tool that can only ever escalate is not a triage tool. Internal mail, a
known vendor, and a mailing list you actually subscribed to should be able
to say so. The trust granted here is partial (weight 0.6, clamped by the
rulepack's `trust.max_factor` of 0.9) because an allowlisted domain can
still be spoofed while DKIM verification is unavailable.

## Example

```toml
# baittrace.toml
[allowlist]
domains = ["corp.example"]
```

```
From: Alice Nakamura <alice@corp.example>
```

IDN900 fires, identity indicators are suppressed, and the trust factor
reduces the score from any remaining header findings.

## Known false positives

An allowlisted domain can still be spoofed while DKIM verification is
unavailable, which is why the trust granted here is partial. Do not
allowlist `gmail.com`. Allowlist *your* vendor's sending domain, not a
mailbox provider.
