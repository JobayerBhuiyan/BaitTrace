# IDN004 Display name claims a brand the domain does not belong to

## What it detects

The display name asserts a well-known brand (by confusable-skeleton match
against the brand list) while the message is sent from a domain that is not
in that brand's authorised list. Confidence is higher when the sending domain
is a consumer mailbox provider (`gmail.com`, `outlook.com`, and the rest of
`freemail.txt`).

## Why it matters

A brand does not contact customers from a personal mailbox. `From: "Microsoft
Support" <alerts@gmail.com>` is impersonation even when the domain itself is
not a lookalike. Combined with IDN003 it is the usual shape of a phishing
email: branded display name plus unauthorised domain.

Recognising `microsoft.com` in `From` does **not** reduce the score. Without
DKIM verification the `From` header is a free-text field that anyone can
write, so treating it as evidence of legitimacy would turn the easiest
forgery into a discount. Trust is only granted through the operator's
explicit allowlist (IDN900) until the AUTH analyzer lands.

## Example

```
From: Microsoft Support <account@micros0ft-login.example>
```

The display name claims Microsoft; the domain is not Microsoft's.

## Known false positives

Small businesses and contractors sometimes send brand-related mail from
consumer mailboxes. Allowlist those senders, or accept a medium-confidence
finding and read it alongside the rest of the report.
