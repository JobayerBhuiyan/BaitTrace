# IDN001 Display name contains a different email address

## What it detects

The `From` display name contains an email address whose registrable domain
differs from the actual envelope mailbox. A mail client shows the display
name, so the address a reader sees is not the address that sent the message.

## Why it matters

This is the oldest impersonation trick that still works: `From: "PayPal
<service@paypal.com>" <thief@evil.example>`. The client UI emphasises the
quoted string. Recipients who have been told to "check the sender address"
check the one that was put there for them to check.

## Example

```
From: "Microsoft Support <support@microsoft.com>" <account@micros0ft-login.example>
```

BaitTrace reports the claimed domain (`microsoft.com`) and the actual domain
(`micros0ft-login.example`) as evidence on `header:From`.

## Known false positives

Ticketing systems and mailing lists sometimes put the original sender's
address in the display name when relaying. If that is your environment, disable
IDN001 or allowlist the relay's sending domain.
