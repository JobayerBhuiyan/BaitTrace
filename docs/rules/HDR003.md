# HDR003 Message-ID domain does not match the sender

## What it detects

The domain in the `Message-ID` (the part after `@`) has a different
registrable domain than the `From` address. The Message-ID was generated by
a different organisation than the one the message claims to be from.

## Why it matters

On forged mail the Message-ID is often generated by the sending kit, whose
domain has nothing to do with the impersonated brand. On legitimate mail the
same pattern appears whenever an organisation uses an email service
provider. The rule is therefore corroborative: it matters alongside identity
findings and is weighted down when bulk-mail headers are present.

## Example

```
From: Microsoft Support <account@micros0ft-login.example>
Message-ID: <5f2a9c04-1b77-4a10-9d3e-77bb0c2e1a55@mail-secure.example>
```

The ID was generated at `mail-secure.example`; the message claims to be from
`micros0ft-login.example`.

## Known false positives

Very common and often innocent: any organisation using an email service
provider will have provider-generated Message-IDs. Weighted low deliberately.
The benign `newsletter.eml` sample fires this rule and still scores 16.
