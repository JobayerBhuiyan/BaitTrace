# IDN003 Sender domain resembles a known brand

## What it detects

The sending domain contains a token whose Unicode confusable skeleton (UTS
#39) matches, or is within a length-scaled edit distance of, a known brand
alias — and the sending domain is not in that brand's authorised domain list.

`micros0ft`, `rnicrosoft`, and `mіcrosoft` (Cyrillic і) collapse to the same
skeleton as `microsoft` and are caught by the same code path. The brand list
is data (`src/baittrace/data/brands.toml`), not code.

## Why it matters

Lookalike domains are the core of brand impersonation. A reader glancing at
`account@micros0ft-login.example` is supposed to see Microsoft. The
registrable domain is not Microsoft's, so the resemblance is not legitimate.

An exact skeleton match where the token is *not* literally the brand name
means confusable characters were used, which is deliberate deception and
scores higher than a token that is literally the brand name on someone else's
domain (which has innocent explanations: resellers, franchises).

## Example

```
From: Microsoft Support <account@micros0ft-login.example>
```

The label `micros0ft` reduces to the same skeleton as `microsoft`.
`micros0ft-login.example` is not in Microsoft's `domains` list.

Tokens shorter than five characters are ignored. Aliases like `ups` and `irs`
would match an enormous number of innocent substrings.

## Known false positives

Resellers, franchises, and regional partners legitimately put a brand name in
their domain. Add those domains to the brand entry in `brands.toml`, or to
the operator allowlist. Add your own employer through user config rather than
by editing the bundled list.
