# HDR002 Message-ID is missing

## What it detects

The message carries no `Message-ID` header, or the header is present and
empty. Every normal mail client and mail server sets one as a matter of
course.

## Why it matters

Scripts that assemble phishing from a template often forget the fields a
real client would have filled in. Missing `Message-ID` is a fingerprint of
that assembly, not proof of malice on its own. The rule is weighted low
(`6.0`) so it corroborates rather than drives a verdict.

The check does not consult the current clock or any network state, so a
verdict does not change depending on when it was run.

## Example

A message whose headers include `From`, `To`, `Subject`, and `Date` but no
`Message-ID`.

## Known false positives

Some internal automation and monitoring systems omit `Message-ID`. This is
why the rule is weighted low. If your environment is full of such mail,
disable HDR002 in config rather than living with the noise.
